Botanical Intelligence / MANS 2026 deployment

システムはどう動くか — 動作ロジックの全体図

M5Stack 30-50 台 (3-5 クラスタ)・センサー 1-2 系統・モニター PC 1 台で構成する MANS 版 Botanical Intelligence の動作原理。CCBT『平行森林』(100台) のコードを下地に、 デバイス側は無改変・ハブ側の設定ファイルだけで組み替える設計。

1. 全体像 — 信号は左から右へ、言葉は森の中を巡る

2. デバイス ID — IP の末尾がそのまま ID

各デバイスには静的 IP (10.0.0.X) が設定済みで、X がそのままデバイス ID になる (main.py resolve_device_id())。今回もこれを無改変で使う。ID は起動時に次の優先順位で自己解決される:

3. トポロジー — 手で書くのはクラスタ割当だけ

結線の正本は cluster_map_mans.csv (id とクラスタ名の 2 列) だけ。 そこから generate_networks_mans.py が各デバイスの送信先 (To 列) を機械的に導出する。 

# cluster_map_mans.csv (手編集)          # networks_mans.csv (自動生成)
id,cluster,note                           ID,IP,To
23,A,入口看板側          ──generate──▶    23,10.0.0.23,"42,31,47"   ← リング両隣+ブリッジ
31,A,                                     31,10.0.0.31,"23,42"      ← リング両隣
42,A,                                     42,10.0.0.42,"31,23"
47,B,BOOK BUS 前                          ...(未使用 ID の行は To 空欄で無害)

3a. クラスタ内 = 双方向リング (故障に強い)

3b. クラスタ間 = ゲートを繋ぐブリッジ (既定 ON)

4. トークンリレー — 言葉は数を数えながら旅をする

デバイス間を流れるメッセージは 1 種類だけ: /bi/input [text, soft_prefix_b64, relay_count]。 受け取った言葉は捨てられず、次の生成の材料に混ざる。relay_count が上限に達すると静かに消える。

5. 1 台のデバイスの中 — 4 相サイクルと声の生成

6. センサー → soft_prefix — 植物の信号が言葉の揺らぎになる

段階処理実体
1. 計測センサーが植物の信号を拾う (AE / マイク RMS など、種別は確定待ち)ハブ PC に入力
2. 正規化キャリブレーション期間の中央値でスケール → 0-1 の強度にinput_controller
3. 量子化閾値 0.25 / 0.5 / 0.75 で 4 段階 [0, 0.1, 1, 10] の soft_prefix 値にsoft_prefix.py
4. 送信種文 (詩句) と束ねて、割当クラスタのゲートへ OSC 送信/bi/input, count=0
5. 伝播ゲートから先はリレー任せ — 揺らぎがクラスタを越えて広がる図4-5
soft_prefix 値の意味: 0 = 揺らぎなし (整った言葉) → 10 = 強い揺らぎ (壊れた言葉)。 植物の信号が強い瞬間ほど、森の言葉が乱れる。センサー→クラスタの割当は config で持ち、 「センサー A は東の茂みに、B は西に効く」のような対応を作れる (実装は次工程)。

7. 運用 — 手で触るのは 1 ファイル、あとは 3 コマンド

8. ファイルと役割

ファイル役割誰が書くか
config/cluster_map_mans.csvID → クラスタ割当。設計の唯一の正本人間 (手編集)
tools/generate_networks_mans.pymap → networks CSV 生成 + validator (重複/範囲外/到達性)—
config/networks_mans.csv生成物。各デバイスの送信先 (To)。CCBT 互換 100 行形式自動生成

main.py / bi/controller.pyデバイス側本体 (ID 自己解決 / 4 相サイクル / リレー)。無改変—

パラメタ値意味
